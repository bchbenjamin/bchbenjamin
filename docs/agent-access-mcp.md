# Scoped REST and MCP agent access

The platform exposes a small, explicit agent surface. Agent API keys are generated by the owner in the private admin workspace, contain 256 bits of random entropy, and are stored only as SHA-256 hashes. The plaintext is returned once at creation. Keys expire after 90 days by default (owner may select 1–365 days) and can be revoked immediately.

## Scopes

- `portfolio:read`: read the published profile and project list/detail.
- `portfolio:propose`: submit proposed content changes to the human review queue.

Tokens may have either or both scopes. The API does not offer a direct agent-write scope.

## REST endpoints

- `GET /api/v1/agent/profile`
- `GET /api/v1/agent/projects`
- `GET /api/v1/agent/projects/{slug}`
- `POST /api/v1/agent/proposals`

All requests use `Authorization: Bearer bch_pat_...`. Agent routes return HTTP 401 for missing or invalid credentials. The only accepted scopes are `portfolio:read` and `portfolio:propose`.

A proposal specifies a resource (`profile`, `projects`, `experience`, `education`, `skills`, `skill-groups` or `achievements`), operation (`CREATE`, `UPDATE`, `DELETE`), optional target UUID and JSON payload. It enters `PENDING_REVIEW`. The owner can approve or reject it in the admin workspace. Approval records the decision but does not apply the change automatically; the owner applies the reviewed edit through the CMS. This keeps an explicit human approval boundary between agents and canonical profile data.

## MCP endpoint

- URL: `/mcp`
- Transport: stateless Streamable HTTP-compatible JSON-RPC POST.
- Protocol version: `2025-03-26`.
- Authentication: same scoped bearer token.

Tools exposed by scope:

- `portfolio_get_profile`
- `portfolio_list_projects`
- `portfolio_create_change_proposal`

The proposal tool creates a pending human-review item; it never mutates the portfolio. The MCP endpoint is stateless and does not issue a session ID. Clients should send `Accept: application/json` and `Content-Type: application/json`, and include `MCP-Protocol-Version: 2025-03-26` after initialization.

## Operational notes

- Token plaintext is never logged or stored.
- Revocation and creation events are added to the admin audit log.
- Agent routes are exempted from CSRF only because they authenticate exclusively with bearer tokens, not browser cookies.
- Rate limiting and usage quotas are part of Phase 8; until then, issue tokens only to trusted agents and revoke unused keys.

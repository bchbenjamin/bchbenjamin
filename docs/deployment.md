# Deployment runbook

## Architecture

- **Vercel:** Next.js 16 frontend, imported from the repository root (`.`).
- **Render:** Java 21 Spring Boot API, built from `backend/Dockerfile`.
- **Render Postgres:** persistent canonical CMS, contact-submission and integration data.
- **External AI gateway:** configured with server-side Render secrets; it is never called directly by the browser.
- **Gmail SMTP:** outbound verification and owner notifications. Owner replies in primary Gmail use the verified sender's `Reply-To` address.

## Render deployment

1. Connect `bchbenjamin/bchbenjamin` to Render and create a Blueprint using the root `render.yaml`.
2. Review the plan and region before applying. The Blueprint uses paid always-on backend compute and a paid managed Postgres plan; this avoids the Free service sleep and Free Postgres 30-day expiration limitations.
3. Add the requested OAuth, AI and SMTP secret values during Blueprint setup. For Gmail SMTP, use an App Password if Google offers it for the alternate Gmail account. `CONTACT_FROM_EMAIL` should match `SMTP_USERNAME`.
4. Wait for the first deploy and verify `https://<render-service>.onrender.com/actuator/health` returns HTTP 200.
5. Add `api.bchbenjamin.in` as a custom domain on the Render service and configure the DNS record Render provides. Wait for TLS provisioning.
6. Update Render `FRONTEND_URL` and `ALLOWED_ORIGINS` if the canonical frontend host changes.
7. Register OAuth redirect URIs on Google and LinkedIn exactly as `https://api.bchbenjamin.in/login/oauth2/code/google`, `.../linkedin` and `.../linkedin-publisher`.
8. Set `ADMIN_ALLOWED_SUBJECTS` to exact immutable `issuer|sub` pairs. Do not use email addresses as identity keys.

## Vercel deployment

1. Import `bchbenjamin/bchbenjamin` and select root directory `.` and framework Next.js.
2. Set Node.js 24.x.
3. Set `API_BASE_URL=https://api.bchbenjamin.in` for server-side content fetches.
4. Set `NEXT_PUBLIC_API_BASE_URL=https://api.bchbenjamin.in` for browser-side admin and contact requests. This value is public and must never contain credentials.
5. Deploy a Preview first. Verify public pages, project pages, resume PDF, contact submission, email verification and `/admin` sign-in.
6. Attach `bchbenjamin.in` and `www.bchbenjamin.in` in Vercel and configure the DNS records it provides. Choose one canonical host and redirect the other.

## Contact mail setup

- `CONTACT_AI_BASE_URL`, `CONTACT_AI_API_KEY`, `CONTACT_AI_MODEL` configure an OpenAI-compatible `/v1/chat/completions` endpoint. If missing or unavailable, the system fails closed to owner review.
- The AI can assess spam, risk and consistency of the submitted identity claims. It cannot verify that a person or organisation exists. Email verification proves control of the supplied mailbox, not legal identity.
- `SMTP_USERNAME` and `SMTP_APP_PASSWORD` authenticate the alternate Gmail account. `CONTACT_FROM_EMAIL` must match that account. `CONTACT_INBOX_EMAIL` is the primary Gmail inbox.
- A verified, AI-approved enquiry is delivered to the primary inbox with `Reply-To` set to the sender. Reply from primary Gmail directly to the visitor; no inbound SMTP server or reply webhook is required.
- AI-review submissions appear in the authenticated `/admin` contact queue. Failed notification sends can be retried there.

## Database and security

- Flyway runs migrations on API startup. Never manually edit the schema in production.
- `TOKEN_ENCRYPTION_KEY` and `CONTACT_IP_HASH_SALT` are generated by the Blueprint. Back up the encryption key securely; losing it makes stored LinkedIn tokens unrecoverable.
- Configure managed Postgres backups/PITR and perform a restore drill before treating the site as production-critical.
- Render Free web services block outbound SMTP ports 25, 465 and 587; this Blueprint uses paid compute so Gmail SMTP can connect. Free web services also sleep after inactivity, and Free Postgres expires after 30 days.
- The contact API rate limit is per backend instance. If you horizontally scale, enforce global quotas at an API gateway or shared rate-limit store.
- Set up Render alerts/log drains and monitor database storage, email delivery failures and AI provider errors.
- Keep the AI API key, Gmail App Password, OAuth secrets and database credentials exclusively in Render's secret environment. Never put them in Vercel `NEXT_PUBLIC_*` variables.

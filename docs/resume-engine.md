# ATS-first resume engine

The resume PDF is generated by the Java API from published PostgreSQL content. It uses HTML/CSS rendered to PDF with OpenHTMLtoPDF and an embedded DejaVu Sans font. The output is a semantic, single-column document with standard section headings and selectable text; project repository URLs are emitted as real PDF hyperlinks.

## Variants

- `long`: full project descriptions and all published projects.
- `short`: short project descriptions and up to three projects; achievements are omitted.
- `resume`: resume-specific project descriptions and published achievements.

Public API: `GET /api/v1/public/resume.pdf?variant=resume`. The Next.js same-origin proxy is `GET /api/resume?variant=resume`.

## Content integrity

The renderer includes profile, skills, experience, education, projects and achievements only when published records exist. Education is currently empty because verified institution, qualification and date details have not been supplied to the CMS. The PDF does not invent them.

Projects now store three purpose-specific descriptions:

- `description`: long-form project explanation.
- `short_description`: compact portfolio card/short resume copy.
- `resume_description`: concise, ATS-oriented contribution summary.

These fields are editable in the authenticated content manager. Keep project claims factual and include measurable outcomes only when they can be substantiated.

## Validation

The PostgreSQL integration suite should verify PDF response status, media type and the `%PDF` file signature. For a full visual and ATS review, download the generated file from a configured API and inspect both its rendered pages and extracted text before treating it as a final job application document.
